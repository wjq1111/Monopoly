# 《我们的家》Git 提交与推送

先读仓库 [协作约定](../../../AGENTS.md) 和 [提交约定](../../../CONTRIBUTING.md#提交约定)。提交类型、中文标题、文件范围和授权规则以协作规范为准，不在技能中维护第二套约定。

## 准备提交

- 查看 `git status --short --branch`、`git diff`、`git diff --cached`、近期提交及远程地址，记录已有暂存内容。按用户本次要求确定包含哪些工作；范围外的改动和暂存保持原样。
- 同时检查已跟踪差异和未跟踪文件，避免漏掉文档、原始素材、`.gd.uid` 或 `.agents/skills/`。检查忽略规则和大文件；项目技能可随仓库提交，个人全局技能、缓存与凭据不属于项目上传范围。
- 依据改动执行协作规范要求的验证。仅修改文档或技能时检查事实、相对链接及技能格式；只有改变代码时才运行 `scripts/check.ps1`。不将之前运行的检查写成刚刚重跑。
- 按明确文件或差异暂存，再核对 `git diff --cached`、`git diff --check` 和 `git diff --cached --check`。一个提交围绕一个目的，中文正文只记录实际改动、验证和必要限制。
- 已有暂存内容不在本次范围时，限定实际提交内容或使用独立索引；仅执行 `git add -- 指定路径` 后普通 `git commit` 仍会夹带原暂存。操作前后核对原暂存内容，使用独立索引后也检查真实索引，避免残留本次文件的反向差异。沿用已有 Git 身份，不编造姓名、邮箱或远程地址。

## 推送与交付

- 用户已授权本次上传或推送，且目标与范围明确时，完成提交后直接推送；仅要求提交时停在本地。技能本身不提供额外授权。
- 推送前获取目标分支状态。保留远程已有提交；如双方都有变更，先审查并整合。存在其他人的工作区或暂存改动时，优先在隔离工作树整合，不依赖自动 stash 保护这些改动。普通上传使用正常推送，不以强制推送、删除远程分支或改写历史解决拒绝。
- 认证、权限或分支保护阻止推送时，保留本地成果，说明具体阻碍；不要绕过限制或循环重试同一失败动作。
- 推送后读取远程分支提交号，与本次提交核对，并查看本地状态。交付仓库链接、分支、提交号、实际检查及仍留在本地的内容；不能只凭本地提交成功宣称上传成功。
