# 《我们的家》开发与交付

本技能作用于本仓库，不改变用户指定的任务范围。说明使用中文，保留必要的文件名、命令和机器标识。

先遵循仓库 [协作约定](../../../AGENTS.md)。按本次职责读取 [开发、素材、写作与提交规范](../../../CONTRIBUTING.md) 的相关部分，通用交付要求集中维护在那里，不为每个岗位复制一套技能。

按改动查阅依据：

- 涉及玩法、数值或剧情：读取 [策划规则整理](../../../docs/故事审阅与开工前条件.md) 的相关部分，保留待定项，不扩展故事。
- 涉及架构、开发顺序或进度：读取 [技术方案与实施计划](../../../docs/技术方案与实施计划.md)，分别记录已实现与计划内容。
- 涉及美术、界面、动画或声音：先读 [素材风格与生成规范](../../../docs/素材风格与生成规范.md)，应用已确认的风格版本与固定基准；记录来源、可用范围及占位、候选、已接入、已验收状态。当前画风仍待定，首次样张与风格变更沿用用户已确认方向或新要求；需要选择新方向时，先准备可比较样例，再请用户决定并记录基准。

将已确认规则落实为当前阶段可验证的成果。界面呈现与规则结算分开，三名玩家中一人作为联机房主，系统负责主持。

生成位图使用已有图像生成能力，界面在 Godot 中实际落地。音效可程序合成、剪辑并接入；当前没有音乐或配音专用生成工具，不承诺一次生成专业原声或完整配音。

每轮执行工作更新 [工作与决策记录](../../../docs/工作与决策记录.md)，记录工作 ID、用户要求、助手决定及其依据、影响、决定人和确认状态，以及完成、未做、阻塞和下一步。逐轮记录不等于逐轮全测；历史补记只用已有证据，不补造时间、用户认可或逐例结果。

测试先读 [测试流程与用例规范](../../../docs/testing/测试流程与用例规范.md)，通过 [需求追踪矩阵](../../../docs/testing/需求追踪矩阵.md) 关联需求版本与用例；脚手架用例见 [M0 测试用例](../../../docs/testing/M0测试用例.md)。工作记录关联用例和运行证据，未实现、阻塞与未运行不得写成通过。

需求开发中只按风险做必要的针对性检查，不每次改动都跑完整流程。一项可验收需求完成后，执行对应需求用例与受影响回归；完整自测用于阶段验收或跨模块整体验证。`scripts/check.ps1` 是可选用的快速入口，`scripts/self_test.ps1` 是完整自测入口。界面走正常输入路由，不能用按钮信号冒充点击；操作系统层真实鼠标覆盖另行说明。逐例对照步骤、预期与实测，截图录像只作证据。按实际游戏尺寸查看画面，声音需实际试听，未听只能报告结构检查；仅文档或布局调整检查来源、链接和受影响布局，不运行完整自测。素材生成不代表成品已验收。

交付说明先写结果，再写实际验证和必要限制。提交或上传项目时使用 [项目 Git 技能](../our-home-git/SKILL.md)，按协作规范组织提交说明，不从写作任务推断推送或发布授权。
