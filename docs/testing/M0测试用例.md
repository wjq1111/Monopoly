# M0 需求对应测试用例

本文件由 tests/test_catalog.json 的同一批条目整理。机器目录是本阶段用例定义的维护入口；修改需求来源或用例后同步本文件，并在对应需求验收时重跑受影响用例。

本套件只覆盖旧 M0 本地三猫开局预览。三人联机、实际战斗顺序、月份、剧情、音频等不能从这些用例推导为通过。完整范围见[需求追踪矩阵](需求追踪矩阵.md)，执行方法见[测试流程与用例规范](测试流程与用例规范.md)。

## 回归范围与入口

机器范围标识为 `legacy_m0`。GUI 固定加载 [src/app/main.tscn](../../src/app/main.tscn)，保留 `TC-M0-*`、`TC-GUI-*`、`TC-VIS-001` 原编号及本地选角语义。测试进程将窗口与内容尺寸设为 1100×760，不修改项目显示配置。

旧预览支持按顺序选择三只不同的猫，并查看初始状态。“重新选择”可以清空重来。这是已存在的 M0 技术交互要求，不增加玩法。

[scripts/self_test.ps1](../../scripts/self_test.ps1) 是本范围的完整回归入口。项目正式主场景现为 `res://src/app/game_shell.tscn`；新的联机入口和棋盘由 [scripts/board_check.ps1](../../scripts/board_check.ps1) 单独检查，其用例与证据不能复用旧 GUI 编号冒充。M0 回归通过不表示新主场景、联网或完整游戏通过。

旧执行报告保留各自输入版本和当时结果；修改本套件范围说明不将旧证据更新为当前版本通过。

## 可执行用例与人工表现检查

所有用例的本轮状态和证据由每次运行报告记录，不在用例定义里预填通过。

### TC-M0-001：三猫默认开局

- 需求：REQ-GAME-001、REQ-INIT-001。
- 层次：domain；优先级：P0。
- 前提：使用当前默认规则，无已有会话。

操作：

1. 以奶牛、三花、布偶顺序建立本地初始状态。
2. 读取三名玩家的角色、等级、当前级经验和饱食度。

预期：

- 恰有三猫，每猫默认1级、0野性、饱食度3/5；不额外加上限。
- 这里只验证本地初始状态，不代表三人联机或系统主持流程已完成。

清理：销毁本例状态；GUI顺序流程按各例前提衔接。

### TC-M0-002：六种选择顺序保留
