## 用户报告与漏测

用户报告“界面分辨率一直在变”，并指出之前用例没发现。登记为 **BUG-UI-001：待复现**。目前尚未取得用户观察到变化时的具体操作、窗口/DPI配置及外窗或内容变化类型；本轮不将其关闭。

上一轮TC-BOARD-002主动依次设置四组尺寸，等待30帧后检查终态；它没有逐帧监控普通操作期间的变化，不能证明窗口和布局一直稳定。旧报告保留原范围，不回写为已覆盖新要求。

## 本轮改动

- 新增固定窗口连续用例：连接、选角、进入棋盘、1～29格查看三轮、仓库/角色/设置/剧情往返及真实服务器更新，棋盘连续观察至少60秒。
- 同时记录含系统边框外窗、Godot内容区、逻辑视口、全局缩放、窗口模式和棋盘/格子矩形；处理帧与实际呈现后均采样，尺寸短暂改变再恢复也判失败。
- `board_check.ps1 -StabilityOnly`仅执行导入与本例；默认功能测试不主动轮转尺寸。原四组尺寸检查须显式加`-ResolutionSweep`，没有运行的TC-BOARD-002标NOT_RUN。测试窗口标题明确标为自动验收。
- 使用独立单猫服务端口27944；只操作本例图形窗口。主动全屏往返在同一局单独验证，普通稳定性阶段不修改窗口。
- 没有改正常游戏的分辨率或强制锁定窗口；当前证据不足以认定生产代码根因。

含边框外窗与内容区分别采集，依据[Godot 4.6 DisplayServer窗口尺寸定义](https://docs.godotengine.org/en/4.6/classes/class_displayserver.html#class-displayserver-method-window-get-size-with-decorations)。截图只包含游戏内容区，不能用截图尺寸代表系统边框。
