# 界面布局与制作顺序

版本：UI-LAYOUT-v001；日期：2026-09-05。

当前交付是可切换查看的界面布局提案。[打开布局稿](layout_v001.html)，或查看[棋盘](previews/board.png)、[三人共读剧情](previews/story.png)与[房间选角](previews/room.png)的静态布局。它不是 Godot 游戏或真实联机演示；已有 M0 代码保持本地脚手架范围。

## 1. 本轮确认与提案边界

用户已明确确认：

- 三名玩家先连接同一局，在房间里选择角色，再进入大富翁棋盘。
- 不论哪只猫触发哪一段剧情，三个人都共同观看并看完；个人事件也面向三人呈现。
- 剧情采用类似四格漫画配文字的形式。这里用四格做示例，不把所有事件硬性限定为四格。
- 先确定各界面的布局，再制作 UI 组件与界面底图，按布局接入。
- 不每次改动都跑完整测试；一项需求完成后，执行相关需求与受影响回归，完整流程留到阶段或跨模块验收。

需求来源见[策划规则](../故事审阅与开工前条件.md)“已确认的联机流程与共同观看”，追踪编号为 REQ-GAME-005、REQ-STORY-010、REQ-STORY-011；未来功能用例为 TC-PLAN-027～029，当前均未实现、未运行。

本稿中的“每人点击看完，再一起继续”、准备按钮、房间地址输入方式及 1600×900 横屏比例是助手的交互和布局提案。它们没有自动成为用户确认的完整联网协议。是否逐页同步、谁提交继续、掉线等待和跳过方式仍待定。

## 2. 整体流程与界面清单

基本流程为：联机入口 → 同局房间与选角 → 大富翁棋盘。剧情在棋盘行动、个人事件、觉醒或战斗条件满足时进入；三人共同看完后，返回原来尚未完成的流程。

| 编号 | 界面 | 布局与主要内容 | 需求依据 |
|---|---|---|---|
| UI-01 | 联机入口 | 左侧标题与创建/加入，右侧三猫和场景；地址输入采用弹层 | REQ-GAME-005、TECH-NET-001 |
| UI-02 | 房间与选角 | 顶部三名连接者，中部三猫角色卡，底部选择顺序与准备状态 | REQ-GAME-005、REQ-ORDER-001、REQ-INIT-001 |
| UI-03 | 大富翁棋盘 | 左侧三猫状态，中间29格与环境，右侧地块详情及当前操作，顶栏月份，下栏仓库/角色/行动记录 | REQ-BOARD-001～029、REQ-MONTH-001～003、REQ-MOVE-001 |
| UI-04 | 三人共读剧情 | 四个分镜区与分别排版的文字，底部三人阅读状态和当前玩家完成操作 | REQ-STORY-010～011、原稿6.png示例 |
| UI-05 | 战斗 | 左侧猫状态，中部敌方/场地/闪避区域，右侧骰子与当前猫操作 | REQ-COMBAT-001～005、REQ-ORDER-001 |
| UI-06 | 小猫仓库 | 中左物品网格，右侧三猫状态、物品用途与操作对象 | REQ-MONTH-001、REQ-STORY-003、REQ-SKILL-015 |
| UI-07 | 角色与成长 | 左侧角色与当前数值，右侧等级能力、二选一和技能详情 | REQ-EXP-001～003、REQ-SKILL-001～015 |
| UI-08 | 濒死与送医 | 状态说明、可行动同伴、医院目标；移动过程仍在棋盘显示 | REQ-RESCUE-001～004 |
| UI-09 | 结局 | 结局画面与原稿文字，保留三人共读状态；复用剧情呈现组件 | REQ-STORY-008、010～011 |

不为每个地块单独制作整页 UI。捕猎、抽签、猜大小、抽卡、训练、兑换、技能选点/重投/传送、同伴同意、终战入口选择、战斗结果和失败救场使用共用的事件、选项与结果组件。具体内容按原稿逐项接入。

设置使用简单弹层；连接异常、断线等待、存档与恢复提示也采用共用弹层。布局中的通用弹层只确定位置，相关操作权限、网络行为和未定规则保持待定。

## 3. 三个核心界面先确定

### 房间与选角

从加入同一局开始，三名玩家的身份与连接状态一直可见。三只猫各自只允许被一名玩家占用；本稿可在上方的演示视角中切换玩家，依次选择和准备。

角色名称、兄弟关系、默认等级1、野性0/10及饱食度3/5来自已有策划。选择顺序单独展示，供后续猫的战斗顺序使用，不按三花、布偶、奶牛的名称重新排序。

“准备完成后进入棋盘”为布局提案。演示中的三名连接者是本地样例，没有真正创建房间、身份验证、占位竞态或网络同步。

### 大富翁棋盘

原棋盘是 7×7 格位布局，29个有效地块。布局稿按[原棋盘图](../主线剧情故事截图/棋盘大致样子.png)保留位置，不将编号强行串成外围闭环，也不绘制假定的行走方向。原图中9与10不相邻，4邻接5和10，9邻接15；普通方向与岔路处理仍须裁定。

本稿以约672×672的正方形区域放置棋盘。地块名称、编号、选中状态和三猫棋子单独绘制；地图底图只承担环境与空间，不承载动态文字。点击地块只改变查看内容，不模拟掷骰或移动。

左侧保留三猫的等级、野性、饱食度、行动和异常状态位置；右侧切换所选地块与当前行动选项。实际当前任务和行动记录使用同一栏的折叠/详情空间，不能再叠加遮住棋盘的大面板。

共同观看剧情不等于棋子移动。寻母时其他猫原位、终战选择开战后才集合、觉醒只移动对应猫，仍遵循原规则。

### 漫画剧情

本轮四格采用2×2排布，阅读顺序为左上→右上→左下→右下，每格文字独立于图片。长剧情可以由多页分镜承载；本稿没有决定所有玩家必须同步翻每一页。

样例取原稿6.png的连续片段：回到烂尾楼 → 被施工人员赶走 → 天色转暗寻找庇护 → 在森林公园相互依偎。文字是原稿摘要用于占位，没有新写对白。当前是下雨版本；冬季需按原稿替换为下雪，后续制作保留对应版本。

在布局演示中，每名玩家可以点击“我看完了”，只记录本人的阅读状态；1/3、2/3时“继续”保持禁用，3/3时可查看一起继续的状态。这个动作只说明交互意图，不证明真实三端已经同步，也不确定由谁最终发出继续命令。

个人剧情也进入共读界面，但不把奖励改为三人各领一次，不改变触发猫与原有主线/个人事件优先级。剧情里的共同出镜不推导棋盘全队传送。

## 4. 从布局到素材的制作顺序

| 顺序 | 交付物 | 为什么先做它 | 完成标志 |
|---|---|---|---|
| 1 | 界面布局与状态稿 | 决定玩家看哪里、操作哪里、画面需要留多大空间 | 核对流程、信息层次、等待/禁用等状态和原稿来源 |
| 2 | 共用 UI 组件和三张核心页面 | 房间、棋盘、漫画先共用同一套字体、间距、按钮和面板 | 在 Godot 中完成本项界面需求，再检查实际显示与输入 |
| 3 | 按布局尺寸制作底图、角色和图标 | 已知画面比例、按钮位置和文字留白，减少生成后大幅裁切 | 固定基准、实际参考、提示词与输出尺寸均有记录 |
| 4 | 接入一段共同剧情 | 验证UI、画面、文字与多人等待是否一起工作 | 对应联机需求完成后，运行三端相关用例 |
| 5 | 按同一组件扩展余下界面 | 已有原型和风格基准可复用 | 每项需求结束时验证相关行为，阶段结束再做完整验收 |

UI 的字体、文字、按钮、选中/禁用/等待状态和动态数值由 Godot Theme 与可复用节点生成。必要的装饰纹理、九宫格边框和图标可使用图片；不能把整张交互界面烘焙成一幅含文字的大图。

底图生成顺序按使用价值安排：三张核心界面的底图与分镜 → 当前可玩流程所需地块/战斗/医院 → 其余章节。先为同一画面完成有明确比例和留白的任务单，再生成，不先批量出一堆没有使用位置的素材。

## 5. 素材任务单与暂定规格

下表为制作建议，未生成、未确认，不代表正式风格。正式规格在组件落到 Godot 并核对适配后锁定。

| 素材组 | 本稿使用位置 | 建议生产规格与必须保留的留白 |
|---|---|---|
| 联机入口背景 | UI-01全屏 | 16:9，1920×1080起；标题与按钮所在左侧保持低细节 |
| 角色肖像 | UI-02、侧栏、角色页 | 三猫各一张同规格1024×1024；头像与较大卡片采用不同裁切规格，花纹一致 |
| 房间底图 | UI-02背景 | 16:9，1920×1080；三个角色卡与底部准备栏不能被高反差细节干扰 |
| 棋盘环境 | UI-03中央正方形 | 2048×2048；按原格位遮罩留出29个地块区域，不画编号、文字或棋子 |
| 分镜画面 | UI-04每格左侧区域 | 本稿每幅约410×312，建议4:3、1024×768起；文字另排，不写入画面 |
| 战斗场景 | UI-05中央场地 | 按最终场地区域比例制作；保留猫、敌方动作及闪避位置，UI不烘焙在背景内 |
| 物品图标 | UI-06物品卡 | 256×256透明底起，按实际缩小尺寸检查辨识，复用同一描边与视角 |
| 医院与结局插图 | UI-08、UI-09 | 按最终容器比例制作，沿用已定角色与场景基准，不新增剧情 |
| 共用UI装饰 | 所有页面 | 面板纹理/边框与图标拆件；按钮三态及字体颜色存入共享Theme |

每次生成遵循[素材风格与生成规范](../素材风格与生成规范.md)：使用当前固定基准和必要的实际图像参考，记录允许变化的内容、完整提示词、版本、来源、尺寸及检查结果。

本稿使用已有三张角色候选作比例参考：三花 v001、用户布偶参考、用户奶牛参考。它们没有因此成为正式角色设定。纸色、鼠尾草绿和深墨色仅用于当前布局阅读；正式配色、字体和画风仍待反馈。

布局检查记录见[布局检查记录](布局检查记录_v001.md)。浏览器画面和演示交互只说明此布局文件可供查看；它们不计为 TC-PLAN-027～029 的游戏功能通过。
