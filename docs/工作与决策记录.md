# 工作与决策记录

本文件记录每轮实际工作、助手替用户作出的选择，以及需求、用例和运行证据。详细填写与测试要求见 [协作规范](../CONTRIBUTING.md)、[测试流程与用例规范](testing/测试流程与用例规范.md) 和 [需求追踪矩阵](testing/需求追踪矩阵.md)。

历史补记只归纳现有对话、文档与产物，不声称是当时保存的逐轮日志。没有可靠依据的原发生时间、运行编号和用户认可不补填。历史记录中的“曾记录通过”与本轮重新执行并取得证据的“通过”分别表述。

## 记录方式

- 正式工作使用唯一 ID，例如 `WORK-001`；历史补记使用 `HIST-001`，不据此推算旧对话轮数。
- 每轮开始登记用户要求与范围，执行中补充决定，结束时写清完成、未做、阻塞、需求与用例关联、运行证据和下一步。
- 助手决定在所属工作内编号，例如 `WORK-001-D01`，写明内容、依据、影响、决定人及确认状态。没有新增决定则写“无”。
- “用户已确认”需要明确反馈依据；“助手临时选择”或“助手技术选择”不自动升级为用户确认。后续改变决定时追加结果并关联原条目。
- 游戏需求 ID 与用例 ID 使用测试文档中的真实编号。未涉及游戏行为的纯规范工作注明“不适用”；尚未建立的版本快照、运行报告或证据注明缺口，不伪造关联。
- 后续修正追加到相关记录，保留旧结果及被替代的决定。未实现、阻塞、未运行均不得汇总为通过。
