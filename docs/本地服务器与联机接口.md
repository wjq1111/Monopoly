# 本地服务器与联机接口

更新日期：2026-09-05

当前已实现真实 ENet 房间、选角与准备、三人进入棋盘、服务器状态同步，以及显式单猫模式的调试移动和剧情预览。网络检查 **53 个断言通过**，PowerShell 启动器 **3 项检查通过**。月份推进、掷骰行走、战斗、完整剧情与存档恢复尚未接入。

本轮使用**独立无头 Godot 服务器**，是为验证联机接口作出的工程选择。服务器没有玩家角色；正常模式仍为三名玩家各控制一只猫，系统自动主持，不增加第四个玩家或主持席位。服务器可与一名玩家的客户端运行在同一台电脑上。玩法依据仍为[策划规则整理](故事审阅与开工前条件.md)，后续阶段见[技术方案与实施计划](技术方案与实施计划.md)。

## 1. 启动与停止

以下命令在项目根目录 `E:\MyGames\Monopoly` 的 PowerShell 中执行。使用 Godot `4.6.1.stable.official.14d19694e`；脚本先接受 `-GodotPath`，否则依次查找 `GODOT_BIN`、项目上一级目录中的对应引擎、PATH 中的 `godot`。

### 正常三人房间

启动一个独立隐藏服务器，并保留返回的进程信息：

~~~powershell
$roomServer = .\scripts\server.ps1 -GodotPath 'E:\MyGames\Godot_v4.6.1-stable_win64.exe'
$roomServer
~~~

默认端口为 **UDP 27840**，默认绑定地址为 `*`，即本机可用网络接口。ENet 使用 UDP；RPC 的可靠传输模式由 ENet 提供，不代表这里开了 TCP 服务。[Godot 高层多人网络说明](https://docs.godotengine.org/en/4.6/tutorials/networking/high_level_multiplayer.html)、[ENetMultiplayerPeer](https://docs.godotengine.org/en/4.6/classes/class_enetmultiplayerpeer.html)。

每名玩家启动客户端：

~~~powershell
.\scripts\godot.ps1
~~~

入口填写运行服务器那台电脑的地址，点击“连接同伴的房间”。同机填写 `127.0.0.1`；不同电脑填写服务器的局域网地址。当前界面地址框使用固定端口 `27840`，尚无端口编辑控件。三名玩家进入同一房间，分别选角、准备；任意一名已加入的玩家可在全员准备后请求进入棋盘。

这里提供局域网操作方式，**尚未完成真实三台设备、系统防火墙或公网连接验收**，没有自动端口映射或互联网房间发现服务。连接仍取决于实际网络可达性。

服务器独立运行，关闭客户端不会停止由 PowerShell 单独启动的服务器。结束本次服务时，使用同一会话保留的进程信息：

~~~powershell
Stop-Process -Id $roomServer.PID
~~~

服务没有存档；停止后本局内存状态结束。启动器返回 `PID`、`Port`、`Mode` 和日志路径，日志位于 `.artifacts/server/<启动编号>/`。其 `StartupCheck` 只检查进程是否提前退出，不能单凭存活认定客户端握手成功。端口占用会报错，不自动换端口或停止已有服务。

### 显式单猫调试

客户端入口点击“本机试跑 · 单猫”，会启动自有隐藏服务并连接。也可手动启动：

~~~powershell
$debugServer = .\scripts\server.ps1 -SingleCat
.\scripts\godot.ps1
~~~

手动启动后，客户端点击“连接同伴的房间”，填写 `127.0.0.1`。不要再点击会启动另一服务的“本机试跑 · 单猫”。一名玩家选角并准备后即可进入棋盘，使用“调试 · 移到这里”和“看一段故事”。

省略 `-SingleCat` 时始终要求三名玩家，人数不足不会自动转为单猫模式。调试移动只设置预览落点，不掷骰、不推算路线，也不结算格子奖励。

### 参数与绑定地址

`server.ps1` 支持 `-GodotPath`、`-Port`、`-SingleCat`。需要指定绑定地址时，使用底层入口：

~~~powershell
.\scripts\godot.ps1 -GodotArgs @(
    '--headless',
    '--script', 'res://src/network/server_main.gd',
    '--',
    '--port=27840',
    '--bind=127.0.0.1',
    '--single-cat'
)
~~~

省略 `--bind` 时使用 `*`；`127.0.0.1` 只接受同机连接。省略 `--single-cat` 时使用三人模式。底层入口还接受 `--ready-file=<绝对路径>`：真正绑定端口后写入 `pid`、`port`、`single_cat`，供本地启动和测试检查。父目录须已存在，写入失败则服务退出。

自定义端口的同机客户端可使用现有开发参数：

~~~powershell
.\scripts\godot.ps1 -GodotArgs @('--', '--connect-port=27950')
~~~

此参数只连接 `127.0.0.1`；其他地址与端口组合由 `connect_to_server` 支持，尚未接入界面的端口输入。

## 2. 自建进程生命周期

`start_local_debug_server()` 在开发工程环境下使用当前 Godot 可执行文件创建隐藏无头子进程，绑定 `127.0.0.1`，显式开启单猫模式。它保存本次创建的 PID，检查就绪文件中的 PID 相符后连接，避免端口被占用时误连已有服务。

自建服务就绪最多等待约 6 秒；随后建立 ENet 连接的默认超时为 10 秒。自建服务启动失败或就绪超时报告日志位置，建连超时提示检查地址、端口并重试；不会关闭其他人的服务。主动断开、再次启动、改连其他地址或客户端正常退出时，只清理该客户端自己创建并记录的服务。异步等待带取消标识，旧流程不会在切换连接后覆盖新连接。建连超时使用可取消 Timer，检查启动代次、ENet peer 对象及连接状态；连接成功后立即取消，不影响已经建立的连接。[Godot OS 进程 API](https://docs.godotengine.org/en/4.6/classes/class_os.html)。

`server.ps1` 单独启动的服务不归客户端所有，需要自行停止。客户端异常终止或系统强制结束进程时，退出回调不保证执行；当前没有父进程消失后自动回收服务的监控机制。导出包中的自建服务启动尚未验收，当前接口拒绝非开发引擎环境。

## 3. 文件与职责

| 文件 | 当前职责 |
| --- | --- |
| `src/network/room_state.gd` | 房间状态，选角、准备、开始、调试与阅读命令校验 |
| `src/network/room_network.gd` | ENet 连接、权威 RPC、快照广播、自有服务生命周期 |
| `src/network/server_main.gd` | 无头入口，解析参数、绑定服务、报告就绪 |
| `scripts/server.ps1` | 定位引擎，隐藏启动服务，返回 PID 与日志 |
| `tests/test_room_network.gd` | 独立服务器与同机 ENet 客户端的针对性检查 |

客户端 autoload 节点为 `/root/RoomNetwork`。无头入口优先复用此节点，仅在不存在时创建同名节点；两端使用相同脚本与 RPC 路径。

## 4. 公开接口

信号来自 `RoomNetwork`，界面通过它们刷新显示，不直接写服务器状态。

| 信号 | 含义 |
| --- | --- |
| `snapshot_changed(state: Dictionary)` | 收到或清空当前快照 |
| `connection_state_changed(status: String)` | 连接生命周期变化 |
| `command_failed(message: String)` | 本地连接错误或服务器拒绝原因 |

连接状态包括 `disconnected`、`starting_local_server`、`connecting`、`connected`、`connection_failed`、`server_disconnected`；服务端另有 `server_running`。

| 方法 | 行为与约束 |
| --- | --- |
| `connect_to_server(host: String, port: int) -> void` | 连接服务，取消之前的自有服务启动；地址非空，端口 1–65535 |
| `choose_character(id: StringName) -> void` | 选 `sanhua`、`buou` 或 `nainiu`，只允许在房间阶段使用 |
| `set_ready(value: bool) -> void` | 选角后设置准备状态 |
| `request_start() -> void` | 请求开局，服务器检查人数、角色、全员准备 |
| `request_debug_move(tile_id: int) -> void` | 仅单猫棋盘调试，编号 1–29；阅读期间拒绝 |
| `request_story_demo() -> void` | 仅单猫棋盘调试，开启四段原稿摘要 |
| `mark_story_read(story_id: String) -> void` | 确认剧情已看完，重复确认不会重复结算 |
| `disconnect_from_server() -> void` | 断开、清空快照、停止自己创建的服务 |
| `start_local_debug_server(port: int = 27840) -> void` | 异步启动自有单猫服务并连接 |
| `get_snapshot() -> Dictionary` | 返回快照深拷贝，修改返回值不改变权威状态 |
| `get_local_peer_id() -> int` | 已连接时返回连接身份，其他状态返回 0 |
| `get_connection_status() -> String` | 当前连接状态 |

掉线后如需继续展示“我的猫”，界面应保留本次连接身份并查找最后快照，不能把 `0` 当作玩家身份或补成默认猫。

服务端入口使用 `start_server(port: int = 27840, single_cat: bool = false, bind_address: String = "*") -> Error`。客户端不靠调用该方法占据服务器席位。

## 5. 快照与权威校验

| 字段 | 含义 |
| --- | --- |
| `revision: int` | 服务器状态变化时增加的版本号 |
| `phase: String` | `lobby` 或 `board` |
| `mode: String` | `three_players` 或 `single_cat_debug` |
| `players: Array[Dictionary]` | 已加入玩家；开局后掉线玩家仍保留 |
| `selection_order: Array[String]` | 按玩家首次成功选角顺序排列的角色编号 |
| `story: Dictionary` | 无剧情时 `{}`；有剧情时包含阅读状态 |
| `month: Dictionary` | 当前为 `{}`，没有月份循环 |
| `waiting_reason: String` | 开局后有玩家断线时的等待原因，正常时为空 |

每名玩家包含：

~~~text
peer_id                 ENet 分配的连接身份，大于 1
character_id            "" / "sanhua" / "buou" / "nainiu"
ready                   是否准备
connected               是否仍连接
level                   初始 1
wildness                初始 0；1→2 级需要 10 野性
satiety_units           初始 6，显示饱食度 3
satiety_cap_units       初始 10，显示上限 5
tile_id                 初始 1，仅为本轮棋盘预览落点
~~~

选择其他空闲角色时，当前实现取消准备，并沿用该玩家首次成功选角的位置。开局前离开释放角色和对应选角顺序；开局后离开保留角色、标记离线、进入等待，暂不接纳新连接替代原玩家。

客户端发送操作，服务器从 RPC 获取真实发送者，校验身份、角色唯一性、准备状态、人数与阶段，再更新状态并广播。载荷中的其他玩家 ID 不能改变命令归属。命令与快照使用可靠有序 RPC；服务器身份为 `1`，不计入 `players`。[Godot RPC 与身份说明](https://docs.godotengine.org/en/4.6/tutorials/networking/high_level_multiplayer.html)。

每个连接使用递增命令编号；重复或更旧编号不重新执行，只返回当前快照。这覆盖当前连接内的重放，不是持久化事务、重连凭证或跨会话结算保证。客户端拒绝比已保存版本更旧的快照。普通三人模式即使直接发送调试命令，服务器也拒绝。

## 6. 剧情预览与掉线

剧情字段包含 `id: String`、`title: String`、`lines: Array[String]`、`read_peer_ids: Array[int]`。演示取自原稿第 6 页“返回烂尾楼、被赶出、来到公园入口、小洞避雨”的四段摘要，用于分格画面与文字的呈现接口，不增加故事、发奖励或强制移动。第四段为“三兄弟在森林公园的小洞里躲雨，暂时安顿下来。”此例固定使用非冬季预览文字；当前没有月份推进。格子插图暂作剧情画面占位，不代表四格剧情专用画面已经制作完成。

服务器记录参与者的阅读确认；全部确认后清空剧情，保持位置和棋盘阶段。重复确认已完成的剧情不重复改变状态。“我看完了”是本轮调试流程；正式共读的逐页同步、跳过与恢复裁定仍依策划确认，不能由预览推导。

**可操作的剧情演示入口仅在单猫模式开放。** 本轮网络检查验证单猫阅读结束与防重复逻辑，没有验证真实三名玩家共同阅读的完整交互。三人共同看全部剧情仍是正式需求。

开局后玩家掉线，服务器保留状态并报告等待，不替他确认剧情。与服务器连接丢失时，客户端保留最后快照供展示，拒绝继续发送游戏操作；主动退出则清空快照。自动重连、身份恢复、存档恢复和断线后的正式流程尚未实现。
